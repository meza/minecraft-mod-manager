# Contributing E2E tests

Follow the [repository contribution guide](../CONTRIBUTING.md). Start with the
[testing guide](../docs/contributing/testing/README.md) for architecture, examples and tooling.

- Follow [BDD architecture](../docs/contributing/testing/bdd.md) for runner, action, driver and
  product-assertion responsibilities, and the
  [feature contribution guide](features/CONTRIBUTING.md) for authoring rules.
- Follow [presentation testing](../docs/contributing/testing/presentation.md) for attached checks,
  observation timing and result reporting.
- Follow the [HTTP fixture guide](../docs/contributing/testing/http-fixtures.md) for scenario-owned
  responses and request evidence.
- For documentation-only changes, follow the root
  [verification guidance](../CONTRIBUTING.md#verification).
- For executable E2E work, complete the
  [terminal prerequisites](../docs/contributing/testing/terminal-harness.md#prerequisites), then use
  the [suite workflow](../docs/contributing/testing/terminal-harness.md#running-the-suite). The terminal
  harness guide owns tui-test APIs, process lifecycle and diagnostics.
